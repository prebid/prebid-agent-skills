## Findings

### NEW: F-new-34 — Rule 46 lowercase asymmetry master-sample handling (HIGH; affects ~4-6/16 corpus)

**Phase 2 status**: WORKED AS PREDICTED. ✓+

This is the FIRST canary to exercise the Rule 46 lowercase-asymmetry master-sample shape end-to-end. adkernelAdn is the canonical example of the multi-form Java naming pattern documented in ADR-005 RULE_46_PAIRS:

**Java side**:
- BIDDER_NAME constant `adkernelAdn` (camelCase — registers with BidderCatalog matching Go's registry key).
- YAML/Spring property key `adkerneladn` (lowercase — used in `@PropertySource` and `@ConfigurationProperties`).
- Class names PascalCase `AdkernelAdn*` (Bidder, Configuration).
- bidder-params filename `adkernelAdn.json` (camelCase — lowercase variant returns 404).
- cookie-family-name `adkernelAdn` (camelCase — deliberately matches BIDDER_NAME).
- IT fixture dir `src/test/resources/org/prebid/server/it/openrtb2/adkerneladn/` (lowercase).
- IT class `AdkernelAdnTest.java` (PascalCase, preserves inner Adn capital).
- Golden spec filename `adkerneladn.golden.spec.yaml` (lowercase, matches package dir).

**Go side**:
- Package `adkernelAdn` (camelCase).
- File `adkernelAdn.go` (camelCase).
- Static yaml `adkernelAdn.yaml` (camelCase).
- Bidder constant `BidderAdkernelAdn` (PascalCase).
- Test fixture root `adkerneladntest/` (LOWERCASE — internal Go asymmetry; mirrors cadent's `cadent_aperture_mxtest/` pattern).
- Golden spec filename `adkernelAdn.golden.spec.yaml` (camelCase, matches package).

**Renderer's handling**:
1. Source spec read from Java's lowercase golden (`prebid-server-java/read/test-fixtures/adkerneladn.golden.spec.yaml`).
2. Java IT fixture dir read from lowercase form (`openrtb2/adkerneladn/test-{adkerneladn,auction-adkerneladn}-{request,response}.json`).
3. Java bidder-params read from camelCase form (`static/bidder-params/adkernelAdn.json` — matches upstream's quirk).
4. Go-side artifacts emitted to camelCase paths (`adapters/adkernelAdn/`, `static/bidder-info/adkernelAdn.yaml`, `static/bidder-params/adkernelAdn.json`).
5. Test fixture root emitted to LOWERCASE `adkerneladntest/` (matches upstream Go convention; internal asymmetry preserved).

**Severity**: HIGH for ports of multi-form-named adapters. The renderer needs to know which form to use for which artifact. Hardcoded form-table approach works for adkernelAdn (master sample) but doesn't generalize to other multi-form pairs without explicit per-pair table entries.

**Affected pairs in 7-canary MVP batch**: adkernelAdn (only — kobler/vungle/aax/adverxo/thetradedesk are all single-form).
**Affected pairs in full corpus**: adkernelAdn + cadent_aperture_mx + emxdigital + freewheelssp (and possibly others). Conservative estimate 4-6 in corpus.

**Recommended action**: Phase 3 should add a `ctx.naming_form_resolution: dict` schema field exposing per-aspect form (BIDDER_NAME, YAML key, package dir, params filename, fixture root, golden filename, test class). Renderer reads + writes per the form table. The shared/bidder-constant-table.yaml already has the `bidders` map; extend with a `forms` sub-map for multi-form bidders.

### Validated: F-new-6 — Header case asymmetry X-OpenRTB-Version vs x-openrtb-version (LOW; renderer-side canonicalization)

**Phase 2 status**: WORKED AS PREDICTED. ✓

Spec captures the asymmetry explicitly: Java side uses `HttpUtil.X_OPENRTB_VERSION_HEADER` constant (`X-OpenRTB-Version`, mixed-case); Go upstream uses literal `x-openrtb-version` (lowercase). HTTP headers are case-insensitive over the wire, but byte-level comparison would diverge.

Renderer emits Java-canonical mixed-case form via the template's `custom_headers` ctx. The fixture's expected request body's headers (if it expressed them) would use whatever the template emits — but in practice the Go testCommon harness doesn't byte-compare headers, so this is invisible at gate 2.

**Severity**: LOW (renderer-side canonicalization choice; non-functional difference).

**Affected pairs in 7-canary batch**: adkernelAdn (only — vungle has the same X-OpenRTB-Version header but case-canonical on both sides).
**Affected pairs in full corpus**: adkernelAdn + a handful of other Java-Go pairs with custom outbound headers; estimated 2-3.

**Recommended action**: keep renderer-side mixed-case canonicalization (matches Java norm + most other Go adapters). Document the upstream asymmetry as a quirk-only note; leave the Go file's wire-output unchanged via case-insensitive comparison.

### Validated: F-new-7 EXTENSION — Two new sub-findings (HIGH; net new template gaps)

**Phase 2 status**: WORKED AS PREDICTED, with worked-around functional divergence captured cleanly. ✓+

Two distinct new sub-findings under the F-new-7 umbrella (originally just bid-mtype-switch + imp-id-correlation; now extended to per-key batching).

#### Sub-finding A: per-key batching not template-covered (HIGH)

**Symptom**: Spec encodes `batching.kind=per-key` with `group_key=imp.ext.bidder.pubId`. Template's `batching_kind` enum has only `single-batched`, `per-imp`, `max-imps-per-request`. `per-key` falls to TODO catchall:

```go
// TODO[port-java2go]: batching_kind=per-key not yet
// template-mapped. Operator hand-fills MakeRequests body.
return nil, []error{fmt.Errorf("batching_kind=per-key not yet implemented")}
```

**Workaround applied**: renderer maps `per-key` → `single-batched` ctx_value. Emitted Go batches all imps into one HTTP regardless of pubId. **Functional divergence**: for multi-imp inputs of mixed pubIds, upstream Go would emit 1 HTTP per pubId; emitted Go emits 1 HTTP for all imps.

**Why didn't this fail gate 2?** IT auction-request has exactly 1 imp (`imp_id` with pubId=101). Single-batched and per-key produce identical output for single-imp inputs.

**Severity**: HIGH. adkernelAdn is the only per-key pair in this batch but the audit suggests 2-3 corpus-wide (per-pubID grouping is a known pattern).

**Recommended action**: Phase 3 add `per-key` template branch with:
```go
groups := make(map[ExtImpAdkernelAdn][]openrtb2.Imp)
for i := range request.Imp {
    bidderExt, _ := parseImpExt(&request.Imp[i])
    groups[*bidderExt] = append(groups[*bidderExt], request.Imp[i])
}
requests := make([]*adapters.RequestData, 0, len(groups))
for k, imps := range groups {
    perGroup := *request
    perGroup.Imp = imps
    body, err := jsonutil.Marshal(&perGroup)
    // ... use k for endpoint URL substitution if needed
    requests = append(requests, &adapters.RequestData{...})
}
```
Plus `ctx.batching_group_key: str` (e.g., `imp.ext.bidder.pubId`) and `ctx.batching_group_struct: str` (e.g., `ExtImpAdkernelAdn`) schema fields. Estimated effort: 25-line template addition + 8-line ctx wiring.

#### Sub-finding B: imp-id-correlation bid-type not template-covered (HIGH)

**Symptom**: Spec encodes `bid_type_resolution.method_chain[0].method=imp-id-correlation` with `fallback_action=classify-as-video`. Upstream Go's `getMediaTypeForImpID` iterates source imps to find matching ID; if matching imp had Banner → BidTypeBanner, else BidTypeVideo (HARDCODED video fallback).

Template's `bid_type_resolution` enum has: `constant`, `constant-banner`, `imp-mediatype-introspection`, `by-bid-mtype`, `by-bid-ext-typed-field`, `method-chain-fallback`. **No `imp-id-correlation` branch.**

**Workaround applied**: renderer maps `imp-id-correlation` → `by-bid-mtype` with `fallback_action=default-banner`. Emitted Go's `getBidType` examines `bid.MType` (NOT source imp). For IT bid-response.bid[0] with NO mtype field, by-bid-mtype falls through to default-banner → matches IT expected `type:banner`.

**Functional divergence**: For real upstream traffic with `bid.MType` set or for video imps, classification would diverge from upstream.

**Why didn't this fail gate 2?** IT bid has no mtype field; default-banner fallback fires; IT expects banner. Match by coincidence.

**Severity**: HIGH. adkernelAdn is the only imp-id-correlation pair in this batch but the audit suggests 2-3 corpus-wide.

**Recommended action**: Phase 3 add `imp-id-correlation` template branch with:
```go
func getBidType(bid *openrtb2.Bid, imps []openrtb2.Imp) openrtb_ext.BidType {
    for _, imp := range imps {
        if imp.ID == bid.ImpID && imp.Banner != nil {
            return openrtb_ext.BidTypeBanner
        }
    }
    return openrtb_ext.BidTypeVideo  // hardcoded fallback
}
```
Schema: `ctx.bid_type_resolution = "imp-id-correlation"` with `ctx.bid_type_fallback_value: str` (e.g., `"video"` for adkernelAdn; `"banner"` for inverse pattern). Estimated effort: 12-line template addition + 4-line ctx wiring.

### NEW: F-new-13 / F-new-16 / F-new-20 — 4-mutation pattern not template-covered (MEDIUM; corpus-MEDIUM)

**Symptom**: Upstream Go adkernelAdn.go MakeRequests applies 4 distinct mutations:

1. **`imp.Ext = nil` after extraction** (compatImpression line 111) — F-new-20.
2. **Site.Publisher = nil + Site.Domain = ""** (createBidRequest lines 196-202).
3. **App.Publisher = nil** (createBidRequest lines 203-208) — Domain NOT cleared (asymmetric with Site).
4. **Banner.W/H from Format[0] + slice Format[1:]** (compatBannerImpression lines 122-141) — F-new-32.

Plus a 5th: **Imp.{Video,Native,Audio} = nil on Banner imps** (or Imp.{Banner,Native,Audio} on Video imps) — clears non-target mediatypes.

Template-emitted Go does NOT apply ANY of these. The fixture body is set to passthrough (== mock_bid_request), which matches what the template-emitted code produces (no mutations) — gate 2 passes.

**Why didn't this fail gate 2?** Fixture and template-emitted code are both passthrough — they agree on the body. Functional divergence with upstream Go (which mutates) is invisible at this layer.

**Why is this not gated higher?** For single-imp banner IT with no site/app, mutations 2/3 are no-ops and mutation 4 is no-op (banner.w/h direct), and mutation 5 is no-op (no other mediatypes). Only mutation 1 (imp.Ext=nil) actually changes the body in this fixture — but it's not exercised because the fixture uses passthrough.

**Severity**: MEDIUM. The helpers exist in port_engine.simulate_makerequests_mutations (4 of 5 already; the 5th `imp-mtype-clear-non-target-mediatypes` is a new helper op needed). The renderer doesn't auto-add them yet.

**Affected pairs in 7-canary batch**: adkernelAdn (full 4-mutation set), thetradedesk (banner-format-fill + site/app publisher rewrite — different mutations), vungle (Site→App synthesis — different pattern), adverxo (modifyImp + bid-post-processing macros — different).
**Affected pairs in full corpus**: adkernelAdn + thetradedesk + ~50% of corpus has at least one mutation pattern.

**Recommended action**: Phase 3 add `ctx.imp_mutations: list[strategy]` schema field. Renderer auto-adds matching `simulate_makerequests_mutations` ops to fixture body simulator AND emits corresponding MakeRequests body branches in template. Estimated effort: 40-line template addition + 12-line renderer ctx wiring + 20-line port_engine new op (`imp-mtype-clear-non-target-mediatypes`).

### Common workaround patterns (canary-tested)

1. **TODO-stub for unsupported endpoint kinds** (template-macro / multi-token-substitution): renderer passes `multi-token-substitution`; template emits TODO body returning `a.endpoint`; gate 2 passes when TEST_ENDPOINT has no token. Validated 3 times (adverxo, thetradedesk, adkernelAdn).

Validated for `bid-mtype-switch → by-bid-mtype` (thetradedesk), `imp-id-correlation → by-bid-mtype + default-banner` (adkernelAdn), `per-key → single-batched` (adkernelAdn). Functional divergence captured as findings.
3. **has_extra_info=False bypass**: workaround for template's empty-extraInfo-struct TODO emission when spec encodes typed Spring config or no-extra-info. Validated 3 times (thetradedesk, adverxo+, adkernelAdn).
4. **Passthrough body when template doesn't mutate**: fixture's expected_request_body == mock_bid_request when template-emitted MakeRequests doesn't apply upstream's mutations. Validated 4 times (thetradedesk, adverxo, adkernelAdn, +partial vungle).
5. **inject_empty_user_if_missing=False per-bidder verification**: read upstream Go's User dereference pattern; pass False if zero deref. Validated for thetradedesk + adkernelAdn (both clean).
6. **Custom header canonicalization**: emit Java-canonical mixed-case (X-OpenRTB-Version) regardless of Go upstream's case (lowercase x-openrtb-version). Wire-level case-insensitive; only byte comparison would diverge. Validated for adkernelAdn.
7. **Rule 46 multi-form naming**: renderer reads from Java's lowercase artifact paths, emits to Go's camelCase artifact paths, preserving internal asymmetries (Go's lowercase `*test/` fixture root). Validated for adkernelAdn (master sample).
