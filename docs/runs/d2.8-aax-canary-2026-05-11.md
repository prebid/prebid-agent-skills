## Methodology notes

- **Why aax is canary 2**: it is the corpus' canonical R5 fail-source-omits sample. The Go-side `bidder-params/aax.json` carries `minLength: 1` on `cid` + `crid` that Java's side omits (Java SHA `c71febfe…004200`, Go SHA `543bb3ef…`). Rule 38 byte-copy preserves source bytes; the resulting Java schema is looser than upstream Go expects. The R5 direction-aware extension in `port_engine.r5_check_at_port_time` consults `cross_language.go_specific_concerns[]` and lifts the state from `pass` → `fail-source-omits-target-constraint`.
- **R5 outcome interpretation**: the `fail-source-omits-target-constraint` state is the **expected** D2.3 §190 outcome — it is a feature of the SKILL (the cross-language fidelity check surfacing a real upstream-Java drift), not a defect. Companion artifacts include `human_todos[].category=upstream-confirmation` and `upstream_bugs_to_file[].target_repo=prebid/prebid-server-java`.
- **F-new-64 (aax-specific, HIGH) deferred to post-MVP**: extending `bidder.java.j2`'s `ext-prebid-video-placement` branch with `ctx.bid_ext_typed_field_path` + `ctx.bid_ext_typed_field_value_map` is a non-trivial template generalization. The F2 sprint scoped to universal blockers + Tier 3 fidelity scaffolds; aax's non-canonical `bid.ext.adCodeType` path remains an operator hand-fill until a second adapter with the same shape surfaces.
- **Cross-canary signal**: aax confirmed F-new-56/58/60/96 universally + introduced F-new-66 (usersync YAML flow-style) as a corpus-wide cosmetic finding; both canary 3 and canary 4 reproduced the geoscope-empty + usersync-flow-style patterns.
