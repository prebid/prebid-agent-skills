### New findings surfaced by canary v2

These all relate to Rule 36 inverse fixture authoring — the Java IT 4-file split → Go flat exemplary transformation has more subtleties than the renderer currently encodes.

#### F-new-9 — bid-response.cur missing (renderer/helper-level)

**Symptom**: After F4 fixture transform, gate 2 failed with `Wrong MakeBids bidderResponse.Currency. Got "", expected "USD"`.

**Root cause**: Java IT `test-kobler-bid-response.json` has no `cur` field. Java's framework defaults Currency to USD when bid-response lacks it. Go's adapter does `bidderResponse.Currency = bidResponse.Cur` directly — empty string when bid-response has no `cur`. Upstream Go fixtures hand-author `cur:USD` in `mockResponse.body` to bridge this.

**Resolution**: when re-authoring the Go fixture, copy `cur` from auction-response to bid-response if missing. Implemented in canary v2 renderer; should be promoted to `port_engine.exemplary_fixture_assemble_java_to_go` (or similar) helper.

**Severity**: HIGH — every Java→Go ported exemplary fixture fails gate 2 without it.

#### F-new-10 — expectedRequest.uri must match Builder test endpoint (renderer-level)

**Symptom**: Gate 2 failed with `httpRequest[0].uri "https://test.example.com/bid" does not match expected "https://bid.essrtb.com/bid/prebid_server_rtb_call"`.

**Root cause**: The kobler_test.go (rendered by `bidder-test.go.j2`) calls `Builder(... config.Adapter{Endpoint: "https://test.example.com/bid"} ...)`. The adapter routes via `cfg.Endpoint` → `a.endpoint` → `expectedRequest.uri`. The fixture must use the test-Builder's `Endpoint` value, NOT the real bidder-info endpoint.

**Resolution**: Renderer hardcodes `TEST_ENDPOINT = "https://test.example.com/bid"` to match `bidder-test.go.j2`'s Builder invocation. Should be promoted to a single source of truth (e.g., a constant in port_engine that both templates reference).

**Severity**: HIGH — every Java→Go ported fixture fails URI assertion.

#### F-new-11 — expected_bids should derive from bid-response, not auction-response (renderer-level)

**Symptom**: Gate 2 failed with `typedBid[0].bid json did not match expected.` showing extra `exp`, `ext.origbidcpm`, `ext.prebid` fields in the expected JSON.

**Root cause**: Java auction-response captures POST-prebid-server-processing state with all framework enrichments (exp, ext.origbidcpm, ext.prebid.meta). The Go adapter's MakeBids returns the bare bid the upstream sent (post-getBidType), NOT the enriched form. Renderer was deriving `expected_bids` from auction-response → fixture expected enriched bids → adapter returned bare bids → mismatch.

**Resolution**: Renderer derives `expected_bids` from `bid_response.seatbid[].bid[]` (the bare bids the upstream returned), not auction-response. Plus the type field that getBidType computes.

**Severity**: HIGH — every Java→Go ported fixture fails bid-shape assertion.

#### F-new-12 — exemplary-fixture.json.j2 must emit expectedRequest.impIDs (TEMPLATE-LEVEL — fixed in this commit)

**Symptom**: Gate 2 failed with `expected.ImpIDs must contain at least one imp ID`.

**Root cause**: Go's `adapterstest.RunJSONBidderTest` asserts `len(expectedRequest.impIDs) > 0`. The template `exemplary-fixture.json.j2` didn't emit `impIDs` at all.

**Resolution**: Template now emits `"impIDs": {{ call.imp_ids | tojson }}` when `ctx.http_calls[].imp_ids` is provided. Renderer derives from `mockBidRequest.imp[].id`. Render tests added.

**Severity**: HIGH — every Java→Go ported fixture fails impIDs assertion.

#### F-new-13 — expectedRequest.body must match adapter MakeRequests output, not Java IT bid-request (renderer-level)

**Symptom**: Gate 2 failed with `httpRequest[0] json did not match expected` showing 15+ extra/missing fields (secure, tid, at, cur, device, ext.prebid.server, site, source, etc.).

**Root cause**: Java IT `test-kobler-bid-request.json` captures the FULLY ENRICHED bid-request — Java's framework adds many fields (secure, tid, at, cur, ext.prebid.server, site, source, device.ua, etc.) BEFORE the adapter sees the request. The Go adapter (passthrough-style for kobler-emit) marshals the input BidRequest verbatim. The Go adapter's output ≠ Java's IT bid-request capture.

**Resolution**: Renderer sets `expectedRequest.body = mockBidRequest` (the F4-transformed auction-request) for passthrough adapters. For non-passthrough adapters (currency conv, sanitization, etc.), the body should reflect the adapter's transformations on top of mockBidRequest. Long-term: a port_engine helper that constructs the expected-body by simulating the adapter's transformations against mockBidRequest.

**Severity**: HIGH — every Java→Go ported fixture fails JSON-body comparison. The fundamental insight is that Java's IT fixtures are POST-FRAMEWORK and cannot be byte-translated to Go's expectedRequest.body which is POST-ADAPTER.
