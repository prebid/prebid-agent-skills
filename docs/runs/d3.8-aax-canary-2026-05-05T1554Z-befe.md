#### F-new-14 — `legacy-raw-go` per-status handlers (HIGH frequency: 3/16 corpus, ~19%)

**Phase 2 status**: WORKED AS DESIGNED. ✓

Template's `_legacy_raw_go_with_handlers` flag fires when `http_status_kind == "legacy-raw-go"` AND `legacy_raw_status_handlers` is non-empty. Emitted MakeBids head (lines 55-68):

```go
if responseData.StatusCode == http.StatusNoContent {
    return nil, nil
```

- Changes the error message format from `Unexpected status code: %d. Run with request.debug = 1 for more info` to `unexpected status code: %d` (camelcase + no debug suffix)
- Both shifts cause downstream prebid-server consumers to see different error.Code() classifications and different log message contents.

**Status-400 and Status-404 supplemental fixtures both pass**, exercising:

### New: F-new-25 — Bid-type method-chain step 1 with non-canonical field emits TODO (MEDIUM frequency; documented gap)

**Symptom**: aax's bid_type_method_chain step 1 is `by-bid-ext-typed-field` reading `bid.ext.adCodeType` (non-canonical — canonical is `bid.ext.prebid.type`). Template emits TODO comment + falls through to step 2. Functionally:
- For fixtures where bids have NO bid.ext.adCodeType (or non-string adCodeType): step 1 falls through (correct).
- For fixtures where bids have bid.ext.adCodeType="banner"/"video"/"native": step 1 SHOULD return the type but instead falls through to step 2 (by-imp-mediatype). When the bid's imp has ONE matching mediatype, step 2 returns the correct type — happy-path result is identical.
- For fixtures where bids have bid.ext.adCodeType="banner" AND the imp has multi-format (e.g. banner+video+native): step 1 SHOULD return Banner; instead it falls through to step 2 which throws. Cross-language semantic divergence.

**Java IT bid-response has no bid.ext.adCodeType**, so step 1's TODO doesn't matter for the canary. But upstream Go aax fixtures (e.g. `multi-format.json`, `simple-banner.json`) DO test the bid.ext.adCodeType path — those are removed from the sandbox during canary execution (canary tests emitted fixtures only).

**Real-world porting consequence**: For adapters using a non-canonical `bid.ext.X` field with method-chain, the operator MUST hand-fill step 1 with:
1. A typed wrapper struct (`type aaxResponseBidExt struct { AdCodeType string }`)
2. Inline `jsonutil.Unmarshal(bid.Ext, &bidExt)`
3. A switch over the field value mapping to BidType

Captured as `human_todos[].byte-divergence-warning` in port-report.

**Affected pairs in 5-pair batch**: aax (only).
**Affected pairs in full corpus**: any adapter with non-canonical bid.ext typed field path. Audit table line 198 shows F-new-4 (single-step by-bid-ext-typed-field) for appnexus + smarthub which use canonical paths; aax is the multi-step variant with a non-canonical path.

**Severity**: MEDIUM. Either (a) extend template's by-bid-ext-typed-field branch to accept arbitrary field paths + struct names via a new ctx schema field (`step.struct_name` + `step.field_path` + `step.value_mapping`), or (b) document the TODO as the canonical hand-fill path in SKILL.md.

**Recommended action**: option (b) for now; option (a) when a 3rd adapter with a non-canonical field path appears in a canary.

### New: F-new-26 — endpoint_resolution_kind=query-parameter-augmentation is a template TODO stub (MEDIUM; affects 1/5 batch + future)

**Symptom**: aax's Go-side endpoint_resolution_kind is `query-parameter-augmentation` (net/url Query/RawQuery to append `?src=<extraAdapterInfo>`). Template's `resolveEndpoint` body branch enum supports only `static` and `dev-prod-toggle`; everything else emits a TODO comment + returns `a.endpoint` unmodified.

For aax, the emitted resolveEndpoint:
```go
func (a *adapter) resolveEndpoint(request *openrtb2.BidRequest) string {
    // TODO[port-java2go]: endpoint_resolution_kind=query-parameter-augmentation
    // requires per-bidder customization (Rule 11/12/14).
    return a.endpoint
}
```

**Functional consequence**: The emitted Go does NOT append `?src=` to the endpoint URL at request time. Upstream Go aax.go DOES (via buildEndpoint in lines 136-149 + Builder calling buildEndpoint at line 92). The emitted code therefore does NOT match upstream observable behavior — the bidder will receive requests without the `src` query parameter that AAX uses for upstream attribution.

**Captured**: in port-report.json::human_todos[]; operator must hand-fill resolveEndpoint with a buildEndpoint helper.

**Severity**: MEDIUM. Either (a) extend template's resolveEndpoint branch to support `query-parameter-augmentation` (requires `ctx.endpoint_query_param_name` + `ctx.endpoint_query_param_source`), or (b) leave as TODO and operator hand-fills.

**Affected pairs in 5-pair batch**: aax (only).
**Affected pairs in full corpus**: aax + any others using `query-parameter-augmentation`. Audit table line 51-52 shows aax is the only batch member with this kind on the Go side; corpus-wide unknown.

**Recommended action**: option (b) for now; option (a) when a 2nd query-parameter-augmentation adapter surfaces.
