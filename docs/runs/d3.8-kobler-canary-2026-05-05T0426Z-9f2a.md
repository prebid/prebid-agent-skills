## Findings

Findings are NOT auto-applied. Each is a candidate for the Phase F reflection loop or a direct SKILL/template patch.

### F1 — `bidder.go.j2` unconditionally imports `encoding/json` (Critical)

**Symptom**: Gates 1 + 4b FAIL with `"encoding/json" imported and not used` when `ctx.has_extra_info=False`.

**Root cause**: Template `prebid-server-go/port-java2go/templates/bidder.go.j2` lines 46–58 import `encoding/json` unconditionally. Body only uses `json.Unmarshal` inside the `{% if ctx.has_extra_info %}` branch (lines 80–86). When `has_extra_info` is false, import is unused.

**Fix**: Wrap `"encoding/json"` import in `{% if ctx.has_extra_info %}`. One-line template change. **Trivial; safe to apply directly to the template.**

**Severity**: Critical — every kobler-shaped port (no extraInfo) fails to compile.

### F2 — `port-report.json` shape diverges from schema (Critical)

**Symptom**: 20 schema validation errors on first emit (additional/missing properties). The renderer wrote `$schema`, `emitted_files`, `pr_shape`, `registry_inserts`, `bidder_params_sha256_match`, `note` (in rules_consumed), `rule_ref` (in human_todos), `rule_id` (in unresolved_translations) — none of which are in `port-report.schema.json` v0.2.0.

**Root cause**: `port-java2go/SKILL.md` Step 7 references `port_engine.port_report_emit(report, path=...)` for schema-validated write, but the SKILL prose doesn't enumerate the canonical field set. Without the helper running locally (canary inlined the emit), it's easy to drift from the schema. Also, several useful operational fields (e.g., emitted file inventory, registry-insert decisions, bidder_params byte-match flag) are not in the schema and can't be expressed.

**Fix options**:
- (a) Add an example template / canonical-shape reference in SKILL prose.
- (b) Add `additionalProperties: true` for selected blocks where operational metadata is useful.
- (c) Extend schema v0.3.0 to admit the missing fields (`emitted_files`, `registry_inserts`, etc.) — MINOR additive bump.

**Severity**: Critical — operators will repeatedly hit this until the SKILL prose carries an example.

### F3 — Templates emit excessive whitespace; rely entirely on post-emit `gofmt -s -w`

**Symptom**: All 4 emitted `.go` files needed `gofmt -s -w` cleanup. Diffs show empty leading lines, trailing blanks inside import blocks, blanks inside structs, blanks between `}` and EOF. Each comes from Jinja `{% for %}` / `{% if %}` block whitespace.

**Root cause**: Templates use `{% for ... %}` / `{% endfor %}` on their own lines, producing newlines on every iteration. The template comments explicitly say "post-emit `gofmt -s -w` step canonicalizes whatever this template emits", so this is BY DESIGN, but it makes the raw template output hard to read in a code review.

**Fix options**:
- (a) Status quo: rely on gofmt — works, no change needed.
- (b) Add Jinja `{%- for ... -%}` (whitespace-trim) to clean up output.

**Severity**: Low. Cosmetic. Document the design choice in SKILL prose so reviewers don't think it's a bug.

### F4 — Rule 36 inverse fixture transform doesn't translate `imp.ext` shape (Critical)

**Symptom**: Gate 2 FAIL — `failed parsing imp.ext.bidder: expect { or n, but found  `.

**Root cause**: Java's auction-request fixture has `imp.ext = { "kobler": {...} }` (Java per-bidder slot). Go's standard-two-phase unmarshal expects `imp.ext = { "bidder": {...} }` (post-PrebidServer-Go split). The renderer copied the Java auction-request verbatim into `mockBidRequest`, but Rule 36 inverse needs to apply an `imp.ext` shape transformation: rewrite `imp.ext.{bidder_name}` → `imp.ext.bidder`. Same goes for `imp.ext.prebid` (Java) → flat fields (Go) where applicable.

**Fix**: Add a pre-render shape transform in `port-java2go` Step 5 (exemplary fixture authoring) — or add it to the renderer's responsibility per the SKILL's "Rule 36 inverse" prose. This is NOT a template change; it's a preprocessing step before passing context to `exemplary-fixture.json.j2`.

**Severity**: Critical — every Java→Go port produces a fixture that fails to parse. Likely affects all 6 MVP pairs in D3.8 the same way.

### F5 — Currency-conversion logic missing from `bidder.go.j2` body

**Fix**: Add a `{% if ctx.uses_currency_conversion %}` block in MakeRequests + an emitted helper function. Template gap, not a SKILL-level prose gap.

**Severity**: High — every adapter that does currency conversion (~30% of bidders) ships incomplete code.

**Severity**: Low — semantically equivalent (both parse to 0); cosmetic only.
