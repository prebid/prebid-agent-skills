## Methodology notes

- **Why adverxo is canary 4**: it is the corpus' empire-parent edge case — `meta.empire_canonical_master=true` with 3 declared `parent_aliases` but `aliases:[]` empty (the child specs are noted as "future"). Tests whether the SKILL classifier consults the empire-meta fields OR falls back to alias-array-only classification. The current SKILL falls back; the discrepancy is captured as F-new-69 (cross-canary canonical).
- **Java edge case #19 (filename-vs-class-name)**: adverxo's emitted configuration file is `AdverxoBidderConfiguration.java` (not the canonical `AdverxoConfiguration.java`). Upstream Java's `OuterTypeFilename` checkstyle rule + the public-class-name-must-match-file javac rule both require the internal class name to match the filename. Pre-F2 the template hardcoded the `<Root>Configuration` form; F2 Tier 1 added a `ctx.config_class_name` override to support both forms (adverxo + dianomi + adnuntius). F-new-79 (cross-canary canonical) **retired**.
- **`multi-token-substitution` is the third F-new-50 family member**: alongside kobler's `dev-prod-toggle` (canary 1) and thetradedesk's `template-macro` (canary 6), adverxo's `multi-token-substitution` (canary 4) completes the corpus coverage of the 4 endpoint-resolution kinds the F2 Tier 3 step 2 commit scaffolds (`b6f3124` — `dev-prod-toggle`, `query-parameter-augmentation`, `template-macro`, `multi-token-substitution`).
- **Cross-canary signal**: adverxo introduced the per-imp/per-mediatype fixture coverage gap (F-new-68 canary 4 subagent) — IT scenarios emit per exemplary fixture but all reference an identical bid-request/bid-response pair, losing per-mediatype path coverage. Reproduces in vungle + thetradedesk. Operator hand-fills authentic per-mediatype fixtures during Gate 2 hand-off.
