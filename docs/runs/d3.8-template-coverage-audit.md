## Recommended template extensions ordered by priority

### TIER 1 — Must-implement bodies (HIGH-band features that today emit broken or stub code)

1. **F8 fix — Real `getBidType` body for non-trivial bid-type-resolution kinds** (combined ~50% across `method-chain`, `by-bid-mtype`, `by-bid-ext-typed-field`, `bid-mtype-switch`, `constant-video`).
   - Add a `method-chain-fallback` branch (covers 3 pairs / 19% — kobler, beachfront, aax).
   - Generalize the constant branch to `constant-{banner,video,audio,native}` (covers `constant-video` 12% in addition to `constant-banner` 6%).
   - Add a `by-bid-mtype` branch (Rule 23 — switch on `bid.MType`; covers 12% directly + 6% bid-mtype-switch).
   - Add a `by-bid-ext-typed-field` branch with a templated field path (covers 12% — appnexus, smarthub).
   - This **single tier-1 work item** touches ~50% of the corpus directly. Without it, every non-banner-constant adapter ships incorrect bid type defaulting.

2. **F5 — Currency-conversion helper emission** (5/16 = 31%).
   - Add `{% if ctx.uses_currency_conversion %}` block in MakeRequests body emitting the `convertImpCurrency` helper (per upstream `kobler.go` 13-line shape).
   - Imports: `github.com/prebid/prebid-server/{module_version}/currency`.
   - Affects: adverxo, beachfront, kobler, limelightDigital, vungle.

3. **Custom-headers extension** (5/16 = 31%).
   - Promote `standardHeaders()` to consume a `ctx.custom_headers` list (`[{name, value}]`), producing additional `headers.Add(...)` calls.
   - Affects: adkernelAdn (`X-OpenRTB-Version`), elementaltv (same), freewheelssp (`Componentid`), smarthub (`Prebid-Adapter-Ver`), vungle (`X-OpenRTB-Version`).
   - Fix Go-side header-case asymmetry as part of this (canonical mixed-case `X-OpenRTB-Version`).

### TIER 2 — Should-implement bodies (MEDIUM-band features in template enum but TODO body)

4. **`endpoint_resolution_kind=multi-token-substitution`** (3/16 = 19%) and **`single-token-substitution`** (2/16 = 12%) — promote from TODO comment to functional `strings.Replace(a.endpoint, "{X}", v, 1)` body, pulling token names from `ctx.endpoint_macros`. Combined: 5/16 = 31%.

5. **`Rule 35 inverse extraInfo struct field emission`** (3/16 = 19%).
   - The `{% if ctx.has_extra_info %}` block is present, but the struct body is `// TODO[port-java2go]: operator fills fields ...`.
   - Extend ctx with `ctx.extra_info_fields: [{name, json_tag, go_type, ...}]` so the template can emit the struct shape (still letting the operator fill validation tags).
   - Affects: appnexus (`platformId`, `iabCategories`), beachfront (`videoEndpoint`), kobler (`devEndpoint`).

6. **F7 — Device/User sanitization helper** (2/16 = 12% — kobler, beachfront).
   - Per the canary's F7 fix-option, add a separate template `sanitization.go.j2` (or `device-user-sanitize.go.j2`) included conditionally when `ctx.entity_strategies.{Device,User}` are non-passthrough.
   - Worth its own file because the helper is multi-line (rebuild Device with cleared IPs/UA fields, etc.) and would clutter the main template.
   - Lower percentage than F5/F8 but still a clear pattern.

7. **`imp_ext_unmarshal_kind=none`** (2/16 = 12% — aax, optidigital).
   - Add a third branch that skips parseImpExt entirely (no body line, no error path).
   - Currently the `else` branch falls into `direct` shape — semantically incorrect for adapters with no schema fields.

### TIER 3 — Nice-to-have or separate-file (LOW-band gaps)

8. **`endpoint_resolution_kind=template-macro` and `dynamic-template-string`** (combined 3/16 = 19%) — distinct from `multi-token-substitution` because they use Go `text/template` rather than `strings.Replace`. Add as a new enum value; tier-3 because the SKILL likely needs Rule additions first.

9. **F6 dev-prod-toggle real body** (1/16 = 6% — kobler).
   - Currently `{% elif ctx.endpoint_resolution_kind == "dev-prod-toggle" %}` returns `a.endpoint` with a comment. Promote to read `imp.ext.bidder.test` and pick `a.devEndpoint` vs `a.endpoint` (would compose with item 5's extraInfo emission).

10. **Stay as `// TODO` stub** (LOW-band, no demonstrated demand): `multi-endpoint-by-mediatype`, `literal`, `query-parameter-augmentation` (1 occurrence each), `batching=per-key` (adkernelAdn group-by-pubId), `batching=imp-flatten-aggregate` (mediasquare custom body), `iab_category_storage` (appnexus only). For each: emit `human_todos[]` entry in `port-report.json` and let the operator hand-fill.

11. **Separate template file for mediasquare-shape** (1/16 = 6%): mediasquare's `Bidder<MediasquareRequest>` parameterized custom body warrants a dedicated `bidder-custom-body.go.j2` (or out-of-template carve-out) — not feasible to express in the main `bidder.go.j2` flow. Defer until a second custom-body bidder appears.

### Beyond F5–F8 — patterns NOT in template enum at all

These are findings beyond the kobler canary's F5/F6/F7/F8 — discovered while auditing.

- **F-new-1**: `imp_ext_unmarshal_kind=none` — 2/16 (12%; aax, optidigital). Template enum has only `standard-two-phase` and `direct`. Adapters that don't unmarshal imp.ext at all still get a `parseImpExt` function emitted (which then is unused or fails). **Severity: medium**.

- **F-new-2**: `endpoint_resolution_kind=template-macro` — 2/16 (12%; adkernelAdn, thetradedesk). Uses Go `text/template` (`{{.X}}`-style) rather than the `strings.Replace`-style of `single-token-substitution`. Not in template enum. **Severity: medium** (also see ADR-006/-007 macro-form asymmetry notes).

- **F-new-3**: `bid_type_resolution.method_chain[0].method = by-bid-mtype` — 2/16 (12%; adverxo, teqblaze) plus a 3rd variant `bid-mtype-switch` (thetradedesk) that is conceptually identical. None of them appear in the template's `bid_type_resolution` enum. The Rule 23 inverse switch on `bid.MType` integer values is well-known Go-canonical idiom. **Severity: high** — combined with `bid-mtype-switch` this is 3/16 (19%) of the corpus.

- **F-new-4**: `bid_type_resolution.method_chain[0].method = by-bid-ext-typed-field` (single-step, throws) — 2/16 (12%; appnexus, smarthub). Distinct from the `method-chain-fallback` shape (which uses this method as a step then falls back) — these single-step variants throw on missing field. **Severity: medium**.

- **F-new-5**: Synonyms `single-batched` and `per-batch` in `batching.rules[0].kind` — both spec values mean the same thing. Combined frequency is 7/16 (44%). The template enum has `single-batched`; the spec corpus has both spellings without normalization. **Severity: low/spec-hygiene** — the template only matches one token.

- **F-new-6**: Header case asymmetry across Go/Java — `X-OpenRTB-Version` (Java) vs `x-openrtb-version` (Go) on adkernelAdn and elementaltv. Functionally equivalent under HTTP spec, but the template's emitted header should match the Go-canonical form. **Severity: low**.

- **F-new-7**: `bid_type_resolution.method_chain[0].method` values found that warrant separate treatment: `imp-id-correlation` (adkernelAdn), `string-sniff-adm-substring` (emxdigital), `by-response-payload-shape` (mediasquare). Each is a one-off and reasonable to leave as `// TODO` per item 10 above. **Severity: low** (per-bidder).

- **F-new-8**: Mediation-tier alias case (152media is fully alias; `code: null`) — the template/SKILL flow needs an explicit short-circuit when `is_alias=true` and `code: null`. The audit excluded 152media from `code.*` aggregates; the port-skill flow probably needs the same gating to avoid emitting placeholder methods for alias adapters. **Severity: medium** — affects every alias-only port (~6% of bidders by current corpus, but a meaningful population at full scale).

## Methodology notes / caveats

- **Counts are Java-side** unless flagged. Go-side spec values agree on most fields; key Go-only divergences (mostly idiom labels like `in-place` ↔ `immutable-rebuild`, header case, `legacy-raw-go` ↔ `legacy-raw`, `go-data-table` ↔ `yaml-inlined`) are noted in the per-pair table.
- **Sanitization classifier** treats `none`, `null`, `passthrough`, `no-mutation`, `append-if-missing` as "no sanitization"; treats `immutable-rebuild`, `immutable-mutate`, `synthesize-app-replacement`, `replace-with-app-synthesis`, `in-place`, `copy-then-mutate`, `shallow-copy` as "sanitization".
- **`bid_type_resolution` classifier** uses `method_chain[0].method` for single-step chains and labels multi-step chains as `method-chain(N-step,methods...)`. Single-step `hardcoded` is split by `hardcoded_value` into `constant-banner`/`constant-video`/`constant-other`.
- **Aliases**: 152media is the only `is_alias: true` pair; it has `code: null` on both sides and is excluded from `code.*` denominators (N=16 for those features, N=17 for `iab_category_storage` and headers).
- **Whitelabel-only**: smarthub and teqblaze have `whitelabel_only: true` but their parent specs still carry the implementation, so they remain in the implementing N=16.
- **Not audited** in this pass (out of scope per task brief): `tests.fixture_inventory`, `quirks[]`, `cross_language` lifecycle/rename, ext_pojo `flexible_extension_used`, `bidder_class.parameterized_request_type` (mediasquare custom body).
